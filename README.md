# BigPixels 放大台

用开源权重在你自己的机器上还原 bigjpg 那套「AI 无损放大」。跑的是**真模型**，不是演示代码。

```
低分图 ──双三次上采样 / 分块──> 深度卷积网络预测修正 ──> 高清大图
```

**图片不出本机** —— 没有上传、没有队列、没有额度。网页版就是个本地服务，用完关掉窗口即可。

## 快速开始

### 方式一：下打包好的版本（推荐）

到 [Releases](../../releases) 下最新的压缩包，解压到任意目录（路径别带中文也行，带也没事），然后：

| 系统 | 做什么 |
|---|---|
| Windows | **双击 `start_web.bat`** |
| macOS / Linux | `chmod +x start_web.sh && ./start_web.sh` |

之后就不用管了，脚本会把四步走完：

```
找 Python  →  备运行环境  →  自检 15 个权重、缺什么下什么  →  起服务并打开浏览器
```

第一次会慢（要下约 292 MB 权重、装几百 MB 依赖），之后秒开。
中途任何一步失败都会**停在那儿把原因和下一步写清楚**，不会一闪而过 —— 因为双击启动的窗口
跑完就关，不拦一下你根本来不及看。

> **权重为什么不在压缩包里？**
> 一共约 292 MB，GitHub 单文件超 100 MB 就拦，何况每次改代码都重传一遍权重也不合理。
> 所以仓库里只留一份清单（文件名 + **精确到字节**的大小），权重现用现下。
>
> - 默认走国内的 **hf-mirror.com**；有代理可以 `--source hf` 换回原站。
> - 断了直接重跑，**断点续传**（`.part` 记着进度），已经下好的不会再动。
> - 下完还会**再自检一遍**才算成功 —— 判据是"字节数一个不差"，所以「文件在」就等于「文件完整」。
> - 半截文件、git-lfs 指针、下载站塞回来的 HTML 错误页，都会被认出来并重下，
>   而不是留给 onnxruntime 在几分钟后抛一个看不懂的错。

### 方式二：手动来

```bash
# 需要 Python 3.9 以上
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt   # Windows
.venv/bin/python    -m pip install -r requirements.txt    # macOS / Linux

python tools/download_models.py        # 下权重（约 292 MB，走 hf-mirror）
python tools/upscale.py 图片.jpg -o 输出.png --preset art --scale 4    # 命令行单张

python app/server/bootstrap.py          # 上面那两个脚本干的事：环境 → 模型 → 起服务
python app/server/bootstrap.py --check  # 只自检（环境 + 模型），不装不下不起服务
```

网页版起来后是 http://127.0.0.1:8765（换端口：`--port 8766`，或改 `start_web.bat` 顶部那行）。

**服务默认绑在所有网卡上**，所以同一个 Wi-Fi 下的手机、平板也能开 —— 启动时会把该敲的那个
局域网地址一起打出来（`同一个 Wi-Fi 下也能开： http://192.168.x.x:8765/`）。
不想让同网络的人看见，就加 `--host 127.0.0.1`（这个界面没有密码，谁打开都能读写 `outputs/`）。

> 有个坑值得记一下：`0.0.0.0` 是**绑定的通配地址**，意思是「所有网卡都收」，它本身
> **不是一个能连的目的地址**。曾经把它直接拼成 `http://0.0.0.0:8765` 打印出来并甩给浏览器，
> 结果是服务好好的、浏览器说「无法访问此页面」（Chrome 报 `ERR_ADDRESS_INVALID`）——
> 和端口一点关系都没有。现在「绑在哪儿」和「从哪儿能打开」分开算，`smoke.py` 里也钉了断言。

模型如果不全，**不用自己对着文件名点**：启动时会逐个自检，缺哪些直接列出来；
页面上也会顶一条提示，并把预设自动落到还能用的那一档。（CLI 那边 `tools/upscale.py --info` 也能看权重清单。）

## 命令一览

命令行入口全在 `tools/` 下（薄壳，见「目录」那节）。

```bat
:: 二次元插画 4 倍（默认就是 anime，写不写都行）
.venv\Scripts\python.exe tools\upscale.py in.png -o out.png --preset anime --scale 4

:: 想更接近线上观感：加 --clear crisp 和 --bright lift
.venv\Scripts\python.exe tools\upscale.py in.png -o out.png --preset anime --scale 4 --clear crisp --bright lift

:: 卡通/插画用轻量老模型（waifu2x，2× 串联两次，只能 CPU，细节会少一截）
.venv\Scripts\python.exe tools\upscale.py in.png -o out.png --preset art --denoise medium --scale 4

:: 整个目录批量
.venv\Scripts\python.exe tools\upscale.py D:\pics -o D:\out --preset esrgan --scale 4

:: 顺便出一张双三次插值对照图
.venv\Scripts\python.exe tools\upscale.py in.png --compare

:: 看设备和模型状态 / 列预设
.venv\Scripts\python.exe tools\upscale.py --info
.venv\Scripts\python.exe tools\upscale.py --list
```

| 参数 | 取值 | 说明 |
|---|---|---|
| `--preset` | `anime` / `art` / `art-hd` / `esrgan` / `photo` | 图片类型，决定用哪族权重。**二次元插画选 `anime`**（见下） |
| `--scale` | `2` `4` `8` `16` | 目标倍率，不足/超出由网络串联 + Lanczos 收尾补齐 |
| `--denoise` | `none` `low` `medium` `high` `highest` | 降噪档，本质是不同训练噪声水平的权重。只有 waifu2x 系（`art`/`art-hd`/`photo`）有；`anime`/`esrgan` 忽略这一项 |
| `--clear` | `soft` `normal` `crisp`，或直接给数字 | 收尾清晰度。网络出来的是渐变边，这一档决定要不要把它们压回硬边（见下） |
| `--bright` | `off` `lift`，或直接给数字 | 明暗。`off` 默认、最贴原图；`lift` 整体 ×1.019，换线上那种通透感（见下） |
| `--tile` | 默认 256 | 瓦片边长，显存不够就调小 |
| `--device` | `auto` / `dml` / `cpu` | 推理后端 |

## 网页版（`web/`）

双击 `start_web.bat`，或 `.venv\Scripts\python.exe app\server\server.py --port 8765`，浏览器开 http://127.0.0.1:8765。

页面本身分成三份：`web/index.html` 只留骨架，版式在 `web/css/app.css`，行为在 `web/js/app.js`，
服务端按 `/css/` 和 `/js/` 两个前缀把这俩发出去（后缀白名单 + 目录穿越拦截跟 `/fonts/` 同一套）。
分开只是为了改的时候不用在两千行里翻一段 `<script>`；**没有构建步骤**，
改完刷新页面就是新的（这两个前缀故意报 `no-store`，免得看到上一版还以为改坏了）。

页面按 bigjpg 的思路做，六步选完就能出结果：

1. **选图** —— 拖进来，或点左边的示例（三张合成样图：线稿 / 小字截图 / 噪点照片）。
2. **这是什么图** —— 五个预设，各带一句人话说明，**默认落在「动漫插画」**（二次元图这一档细节保留最多）。
3. **放大多少倍** —— 2× / 4× / 8× / 16×，下面**当场算出输出尺寸**（`360 × 240 → 1,440 × 960`）。
4. **要不要降噪** —— 关 / 低 / 中 / 高 / 最高。
5. **线条要多清楚** —— 原样 / 标准 / 更锐。
6. **明暗** —— 原样 / 提亮。**一个开关，默认关**。

至于分块边长、推理后端、权重清单这些，全在「更多设置与引擎信息」里收着，不挡路。

**窄屏（≤700px）下这六步整块收进从底部拉起的抽屉，默认收起。** 手机上一屏就那么高，
真正要看的是那张图，不该被六个步骤占掉。页面上只留一条动作栏：左边写着「选了哪张图 +
现在什么参数」，右边那颗「开始放大」就是主键本身（禁用态和文字跟抽屉里那颗同步，
不会出现"栏上是灰的、其实按得动"）。点动作栏、点遮罩、按 `Esc` 都能拉开／收起。

抽屉最高占 86% 的屏高，上面总留一截光台 —— 你看得见自己是在"拉开一层"，不是"换了一页"。
键盘焦点会跟着进抽屉、并圈在里面，否则 Tab 会一路走到被遮罩盖住的区域去。
宽屏（>700px）一点没变，还是左边控制栏 + 右边光台／放大镜。

### 为什么同样的图，本地会比 bigjpg 糊

**主因不是清晰度档，是预设选错了。** 而且这一半的锅得算在原来的界面上：排第一个的
「卡通 / 插画」用的是 waifu2x CUnet —— 它是 **2× 网络、4× 要靠串联两次**，
两次上采样本身就在丢细节。真正给二次元插画准备的那档（4x-AnimeSharp）原来排在最后，
名字还叫「动漫线稿」、说明写着「线稿专用」，谁都想不到该选它。

同一张 351×1295 的动漫插画、同样 4×，拿细节热点区（眼睛+发丝）的拉普拉斯方差跟
线上 bigjpg 的 4x 卡通比（当作 100%）：

| 预设 | 权重 | 到达 bigjpg 的 |
|---|---|---|
| **动漫插画（现在的默认）** | 4x-AnimeSharp · **原生 4× 一次推理** | **107%** |
| 通用场景 | Real-ESRGAN x4plus · 原生 4× | 37% |
| 卡通 / 插画（轻量） | waifu2x CUnet · 2× **串联两次** | 35% |
| 插画 高清 | waifu2x Swin · 2× **串联两次** | 29% |

差的那三倍，**锐化追不回来**：把增益从 2 拉到 6，锐度数值能冲到 2241（数字上盖过 bigjpg 的 2007），
代价是局部对比度 62.9 vs bigjpg 的 41.3、平块噪声 ×3 —— 那是把对比度和噪点一起抬起来，不是把细节找回来。
bigjpg 的指纹是「**用低得多的对比度拿到两倍的锐度**」（41.3 / 2007），这只有真细节做得到。

顺带一提，这档还更快：waifu2x 系在 DirectML 上会算错、只能退回 CPU，
而 4x-AnimeSharp 跑在 GPU 上。**又快又锐，所以它成了默认。**

那**收尾锐化**（第 5 步「线条要多清楚」）是干什么的？它补的是另一件事：
网络出来的边天然是**渐变**的（1 px 的线摊成 4~7 px 灰带），这一步把边缘收回来。
它只在边缘起作用 —— 平坦区 32×32 块的 std 始终 `0.00`，不会把干净的地方磨出噪点。
**原样**档就是关掉它，跟不做锐化逐像素一致；**更锐**档最接近线上观感。
但它治不了「模型本身没补出来的细节」，那得靠上面那张表。

**一句话**：选对预设是主菜（差 3 倍），收尾锐化是调味（再收一点边）。

### 第 6 步「明暗」是什么，为什么默认关

线上 bigjpg 出来的图看着比原图「通透」一点。对着同一张图的平坦区量了一下，
它其实是**整体提了亮**：亮部 +4.8 灰阶、中间调只 +1.1 灰阶。
这个形状是**乘法**（把每个像素乘一个略大于 1 的数），不是加常数 ——
加法会把中间调一起顶上去、还让纯黑发灰。三种拟合试下来乘法的残差最小
（4.11 灰阶，加常数 4.30，提 gamma 5.88），拟合出来的增益是 **×1.0192**。

所以这一档就是乘 1.019，在「原样 / 提亮」之间切一下：

| | 观感 | 对原图的保真度（PSNR，拿用户那张卡通图量的） |
|---|---|---|
| **原样（默认）** | 跟原图一个亮度 | **32.99 dB** |
| **提亮** | 接近线上那种通透感 | 会掉一点 |

**它是唯一一个「会变差」的档，所以说清楚**：提亮的代价是输出更不像原图。
顺带一提，就算开着提亮，本地对原图的保真度仍高于线上 bigjpg（30.38 dB）——
因为 bigjpg 那 +4 灰阶的提亮本身就是它对原图失真的主要来源之一。
想要「最还原」就保持原样，想要「最像线上」就开提亮，这两个目标在这里是冲突的，
所以做成开关交给你，而不是替你把默认值调过去。

命令行对应 `--bright off|lift`（也可以直接给乘数，比如 `--bright 1.05`）。

出结果后：

- **对照台**：原图和结果叠在同一块深色光台上，拖中间那根竖线来回比（键盘左右键也行）。
  点「**全屏对比**」（或按 `F`）把光台铺满整个屏幕，细节能少缩放一次就少一次失真；
  全屏下 `← →` 微调分割线、`Esc` 退出。全屏时**右侧还会挂一栏实时细节对比** —— 鼠标在左图画面上移动，
  右边就跟着放光标那个框框住的那一块（复用的是同一套三格 DOM，不会重复请求）。
  光台上放的是**缩略预览**（最长边 1600 px）—— 6744×10112 的原始 PNG 交给浏览器解码，光这一步就够它卡一阵了。
- **放大镜**：三格并排，排在右栏最前面（**在「这次改了什么」折叠栏之前** —— 那块一展开
  就是几十行计量表，放大镜跟在后面容易被推出屏幕）——
  原图像素块（最近邻）/ 双三次插值 / AI 结果，**锁在同一块画面、同一个屏幕尺寸**上。
  倍率的单位是「屏幕像素 : 输出像素」，**默认 1:4**：一格装下四倍于格宽的画面，
  一上来就看得见画面是什么，而不是一格糊糊的像素。想看模型的原始像素，按 **1:1**
  （那一档 AI 那格正好是它自己的像素，判断"细节是真补出来的还是编出来的"就看它）。
  比 1:1 更远的档位（1:2 / 1:4 / 1:8）是"看整块结构"，最远那档会被单次取块的边长上限顶住，
  到不了就在标签上写实际能做到的倍率（窗口一窄，`1:8` 可能显示成 `1:7`）—— 不写个按不到的数字。
  倍率有**两个入口，指的是同一件事**：五个预设档一键跳到熟悉的刻度，下面那条**取景滑块**
  用来随便找个合适的。拖了滑块就没有哪个档位亮着（滑块落在两档之间），按了档位滑块自己会挪过去。
  滑块两端由这张图实际能算出来的范围决定，所以从最远到最近一路都拖得动。
  三格不是把整幅图塞进 `background` —— 那样鼠标动一下就要重排一张 68 MP 的位图。
  这里是**按需取块**：只跟服务端要正在看的那一小块真像素。
  倍率比 1:1 更远时把**屏幕尺寸**一并报给服务端（`dw`），让它先缩好再发；
  缩略预览分辨率够撑起这一格时直接从预览取，不够就老实用原像素拼 —— 宁可慢一点，不糊。
  光台上那个十字框**左上角就是放大镜正在看的那一块的左上角**，鼠标推到画面边角它就跟到边角：
  视窗中心钉在鼠标底下、允许有一角伸到图外（伸出去的那半截被光台裁掉），
  不是把视窗整个夹在图里 —— 夹住的话鼠标到边上时框最多只能走到离边半格的地方，永远差一截。
  全屏时这套三格 DOM 会被挪进光台右侧那一栏复用，同样**没有第二条取块通道**。
  两块**同屏**是有账的：光台和放大镜各自都想长，凑一块就超过一屏，一滚就只剩一个
  —— 用户的原话是「你看 这就是鱼和熊掌不可兼得了」。所以放大镜一出来，光台的长边
  从 `56dvh` 收到 `40dvh`、三格边长收成 `25dvh`（两个都由视口高驱动，矮屏幕跟着缩），
  连「结果存哪了」那条提醒也从两块中间搬去了左边控制台。1920×1080 的窗口里
  量出来是 899 px / 982 px 的视口，1600×900（vh≈802）也还塞得下；
  视口比 800 px 还矮（笔记本横屏再压一层书签栏）才需要滚。这条 `shots.py` 会当场判。
- **计量表**（折叠）：尺寸、模型、耗时、吞吐，以及三个老实算出来的指标 —— 回环一致（结果缩回原尺寸与原图的 SSIM/PSNR）、
  锐度增益（对双三次的拉普拉斯方差之比）、体积对比（同尺寸 PNG 大小）。

### 结果放哪：保存模式 / 暂存模式

**默认是保存模式**：每次工程一个文件夹，落在 `outputs/web/` 下，名字就是 `<时间戳>_<图名>_<任务号>`：

```
outputs/web/20260920-191402_SharkGirl_843x1264_e3c72086d0a7/
    input.jpg            原图（后缀随上传）
    result.png           AI 放大结果（模型原生分辨率，无损）
    bicubic.png          双三次基线（输出大到 >30 MP 就不做，省下整幅编码）
    preview-input.png    最长边 1600 的缩略预览（光台用）
    preview-result.png
    tiles/{input,result}/  1024² 瓦片（>4 MP 才切，放大镜按需读几块）
    job.json             这条任务的完整记录（重启后 ?job= 还认它）
```

保存模式下服务**一条都不自动清**。攒多了自己去那个目录删文件夹，或者切下面这个模式。

在「更多设置与引擎信息 → 结果去向」里可以切到**暂存模式**：结果只在服务运行期间留着，
条数/磁盘超了按时间淘汰，**服务一停就清空整个工程目录** —— 所以出图后界面上会当场提醒
「这份结果不会留盘，先按下载存一份」。切模式本身不删任何东西，删除只发生在淘汰和退出那一刻。

模式存在 `outputs/settings.json`，重启后还在；启动时也可以用 `--keep 1|0` 覆盖。

旧版本把产物直接铺在 `outputs/web/` 根下，几十次跑下来是一团。现在启动时会**自动归档**成上面这个结构：
按任务号归堆、按时间戳命名、把原来的文件搬到新位置后再删旧的，所以是无损的、而且幂等（第二次跑一无所获）。
归档时如果发现某条旧结果连记录都没有（早期版本不写 `job.json`），会给它补一份，
能推出来的（尺寸、体积、倍率）补齐，推不出来的（耗时、锐度）留空由界面显示「—」，**不编数字** ——
顺带把那条 `?job=<id>` 链接也救回来了。

### 启动自检

`app/server/server.py` 一起来先把该点的东西点一遍，缺什么直接说：

```
BigPixels 本地版已启动： http://127.0.0.1:8765
  同一个 Wi-Fi 下也能开： http://192.168.1.23:8765
```

第一行是**本机**地址（双击启动时浏览器就开这个），第二行是**同一个 Wi-Fi** 下能用的地址。
端口上已经有服务在跑的话（多半是上一次那个窗口没关），会在最前面直接点出来 ——
Windows 因为 `SO_REUSEADDR` 的语义**允许第二个进程绑同一个端口**（Linux 会拒），
所以两个服务抢一个端口时不会报错，请求只会跑到后起的那个，很容易让人以为"代码改了没生效"。

权重不全的时候会把缺的那几个列出来（哪个文件、现在多少字节、应该是多少）。
双击启动那条路会**自动去下**；单独跑 `app/server/server.py` 的话它会提示你去跑
`python tools/download_models.py`（走 hf-mirror 镜像；慢或者连不上就先开代理再跑）。
页面上同时顶一条提示，并且自动把预设落到还能用的那一档，免得按下去才发现没权重。

页面里图片永远不出这台机器。地址栏会带上任务号（`?job=<id>`），刷新不丢结果，也能把这一份直接发给别人；
`?demo=lineart` 可以预载某张示例，`?theme=dark` 强制深色。

### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 页面 |
| GET | `/fonts/<file>`、`/demo/<file>` | 自托管字体与示例图（做了路径穿越防护 + 后缀白名单） |
| GET | `/api/presets` | 预设、降噪档、倍率、分块档、示例图、模型自检、工程目录、磁盘占用、当前设置 |
| GET | `/api/settings` · POST `?keep=1\|0` | 读 / 改「保存 · 暂存」 |
| POST | `/api/job?preset=&scale=&denoise=&clear=&bright=&tile=&name=` | 请求体直接是图片二进制，返回 `{id}` |
| GET | `/api/job/<id>` | 进度、阶段、耗时、指标、工程目录（`tiled` 说明哪几层预切了块） |
| GET | `/api/job/<id>/input` · `/baseline` · `/result` | 原图 / 双三次基线 / AI 结果（都是 PNG） |
| GET | `/api/job/<id>/result?view=1` | 缩略预览（最长边 1600 px），**光台只碰这个** |
| GET | `/api/job/<id>/detail?layer=&x=&y=&w=&h=&dw=` | 一小块真像素，给放大镜用。`layer` 取 `input` / `bicubic` / `result`；坐标按**输出像素**说，服务端自己换算。`dw` 是"这块最终在屏幕上画多宽" |
| DELETE | `/api/job/<id>` | 删掉一次工程（记录 + 文件夹一起走）。任务还在跑会返回 409 |

`/detail` 的三条规矩：`input` 返回的是**原生输入像素**（客户端按比例放大、`image-rendering:pixelated`，看到的才是真像素块）；
`bicubic` 是**只算这一小块**的双三次，所以输出大到 68 MP 也照样有得比 —— 整幅双三次落盘太贵，那个只在 ≤30 MP 时做；
`dw` 比取块边长小的时候（就是倍率比 1:1 更远那几档），服务端**先缩到屏幕尺寸再发**，
一大块原像素传过去让浏览器缩是白传几十倍字节、白解一次码。1:1 那档 `dw` 正好等于边长，一个像素都不动。

## 实测效果（`tools/bench.py`，160×120 → 640×480）

标尺是合成的高清原图，指标是与原图的 PSNR / SSIM。
下表是**当前代码**跑出来的（含默认的收尾锐化、明暗 `off`）；换成别的 `--clear` / `--bright` 数字会变。

| 样本 | 预设 | 降噪 | PSNR(双三次) | PSNR(AI) | SSIM(双三次) | SSIM(AI) |
|---|---|---|---|---|---|---|
| 卡通插画 | anime | 无 | 22.10 | **24.77** | 0.7896 | **0.9049** |
| 卡通插画 | art | 中 | 22.10 | **22.64** | 0.7896 | **0.8817** |
| 卡通插画 | art-hd | 中 | 22.10 | **23.14** | 0.7896 | **0.8722** |
| 卡通插画 | esrgan | 无 | 22.10 | **23.20** | 0.7896 | **0.8731** |
| 照片 | photo | 中 | 19.97 | 19.50 | 0.6380 | 0.6312 |
| 加噪照片 | photo | 无 | 18.88 | 17.50 | 0.3511 | 0.3570 |
| 加噪照片 | photo | 中 | 18.88 | **18.59** | 0.3511 | **0.5746** |
| 加噪照片 | photo | 最高 | 18.88 | **19.04** | 0.3511 | **0.6244** |

结论：

- **卡通 / 插画**：最好的那一档（`anime`，也就是默认）PSNR **+2.67dB**、SSIM 0.79 → **0.90**，边缘从"糊"变"利"。
  waifu2x 那两行（`art` / `art-hd`）只 +0.5 ~ +1.0dB —— 还是那句话：**2× 串联两次会吃掉细节**，
  选对预设比什么都重要。
- **加噪图**：这才是降噪档的主场，SSIM 0.35 → **0.62**，且档位单调
  （无 0.36 < 中 0.57 < 最高 0.62），证明 noise0~3 是真实生效的独立权重。
- **干净的照片**：跟双三次基本打平（略低一点）。因为样本是 Lanczos 降采样的合成图，
  双三次本来就能还原得不错；真实场景里压缩痕迹重的低分图收益会大得多。
  这也是**为什么 `bench.py` 的门禁不给照片立规矩** —— 感知模型会"造"纹理，拿干净 GT 当尺子只会天天误报。
- 对比图在 `outputs/bench/cmp_*.png`，左中右分别是：像素块原图 / 双三次 / AI。

## 十四个踩过的坑（值得知道）

**1. waifu2x 系模型不是"直出"，尺寸规律得现场拟合。**
`Real-ESRGAN` 是干净的 `out = 4×in`；但 waifu2x 的两个网络内部会吃掉一圈边界：

```
Swin-UNet : out = 2×in − 32
CUnet     : out = 2×in − 72
```

硬编码尺寸必然错位。程序在加载模型时跑两次探针拟合出 `out = a×in + b`，据此自动决定"外扩多少、裁回多少"，并对结果做一次尺寸自检。

**2. DirectML 会对某些模型静默算错。**
尺寸完全正常、图也在出，但内容是废的——waifu2x 系在 DML 上 PSNR 只有 1.98dB，同样代码在 CPU 上是 23.62dB。所以加载时会拿固定输入同时跑 GPU 和 CPU 比对一次，偏差超阈值就自动退回 CPU，结论缓存进 `models/.device_probe.json`。Real-ESRGAN 系在 DML 上是正确的，继续用 GPU。

**3. hf-mirror 的开放区间 Range 会被拒。**
`Range: bytes=0-` 返回 404，但 `bytes=0-4194303` 这种**有限区间**正常。所以 `download_models.py` 按 4MB 分块下载并校验总大小，大文件才能完整拉下来。

**4. Google Fonts 的多字重请求会让同一份文件落盘好几次。**
`family=Archivo:wght@600;700` 这种一次要多个字重的写法，返回的 CSS 是**按子集分组**的（vietnamese / latin-ext / latin 各一段，
每段里再分字重），子集注释写在 `@font-face` **前面**。如果解析时只匹配 `@font-face` 块、让子集名退化成默认值，
就会把 vietnamese / latin-ext 也当成 latin 收进来，同一个文件名被反复覆盖 —— 最后 `archivo-600.woff2` 和 `archivo-700.woff2`
字节完全相同。`app/tools/fetch_fonts.py` 改成**一个字重一个请求**，只认 `/* latin */` 段，抓完再用 md5 去重校验。

另外拉丁子集里没有 `→`(U+2192)，箭头会掉进系统字体、跟等宽数字对不齐，所以单独抓了一份符号子集（1.3KB）。

**5. 一个 68 MP 的输出，能在两个地方把机器拖垮，而且都不报错。**

第一个在服务端。指标里的「锐度增益」要跟双三次基线比，原来的写法是**先把整幅插值成双三次**再取中心 512×512 ——
6744×10112 转成 float32 是 **816 MB**，加上中间那次除以 255 又是 816 MB，峰值 1.56 GB，就为了算一个 0.5 MP 区域的方差。
现在把源图对应区域先裁出来、只插值那一小块，峰值 6.7 MB，而且结果**逐像素一致**（`app/qa/perf_probe.py` 里对着核过）：

```
旧：整幅双三次插值     1.38 s   峰值 1560.9 MB
新：只插值中心那一块   0.01 s   峰值    6.7 MB     最大绝对差 0.000000
```

第二个在浏览器端。34.83 MB 的原尺寸 PNG 直接当 `<img>` 显示，解码出来是 272 MB 的位图；
放大镜再把同一张图当三格 CSS `background`，鼠标一动就重设 `backgroundSize` —— 等于每帧重排一次 68 MP。
现在光台只吃**缩略预览**（1066×1600，1 MB），放大镜改成**按需取块**：大图在任务结束时预切成 1024² 的 PNG 瓦片，
取块时只读命中的那几块，一次几十毫秒、几十 KB。实测横扫对照台 48 次：长任务 0 个、帧间隔稳定 17 ms。

这三处都只改「怎么算、怎么传」，不碰输出本身：下载到的始终是模型原生分辨率的无损 PNG。

**6. 异步取块落地后必须补画一次，否则首屏是空的。**

放大镜改成三格 `<img>` 之后，`drawLoupe()` 的入口是 `if (!S.view || !g) return;`。
而第一次取块时 `S.view` 还是 `null` —— 那次 `drawLoupe()` 直接返回了，`--tilew/--dx/--dy`
一个都没设上。落地后原本只在「需要重新判定」时才补一次，于是**鼠标没动过的话三格一直是黑的**；
手动晃一下鼠标就自己好了。这种「一动就好、不动就坏」的 bug，靠鼠标驱动的截图脚本永远发现不了
（每次拍照前都会先 hover 一下），是拿 DOM 量出来的：`--tilew` 是空字符串、`<img>` 的实际尺寸是 0×0。
修法很简单 —— 落地后无条件再调一次 `updateLoupe()`，顺手把 `recheck` 这个中间状态删掉了。

**7. 全屏那一栏的滚动条，是被一行内联样式顶出来的。**

放大镜倍率从三档加到五档之后，全屏右栏在窄/矮窗口里冒出了横向滚动条（用户报的就是这个）。
一路查下来：栏本身算好的宽度放得下五个键，但 `#zoom` 上挂着一行 `style="flex:0 0 auto"` ——
**内联样式优先级压过所有样式表**，于是「允许折行」能生效、「允许收缩」永远不生效，
五个键硬撑出去。把内联样式删掉、只留样式表里的规则才对。
顺带把 `--fspane` 的固定开销从「按一行标题算」改成「按两行算」：窗口一窄倍率键会折行，
还按一行算高度的话三格就顶出去。**这类只有"窄窗口 + 字段位变多"才会出现的问题，
默认尺寸的截图一张都拍不出来，得专门换个尺寸再量一遍。**

**8. 看得远的那几档，别去瓦片里拼几千万像素。**

1:1 那一档要的是真像素，从 1024² 瓦片里按需读几块就够。
但 1:4 / 1:8 要的是一大块画面压进一格：同样走瓦片拼，一次要拼几千万像素（几十 MB、半秒起），
而这块画面最终只画到几百像素宽 —— 拼出来的绝大部分像素直接扔掉。
缩略预览（最长边 1600）本来就是整幅的一次性缩放，这一档从它取，几十毫秒就回来了，
压到一格大小后屏幕上根本看不出差别。**判断标准是"预览缩完还够不够画这一格"**：
够就走预览，不够（比如 68 MP 的输出配上 1600 的预览）老老实实回原像素那条路 ——
宁可慢一点，也不让 AI 那一格比其他两格糊。1:1 那档的 `dw` 正好等于取块边长，压根不缩，
走的还是原来的路，逐像素不变。

**9. 框框跟不到鼠标，是两个错叠在一起：视窗被夹在图内，而且框是按"中心"摆的。**

用户的原话：「鼠标都到那个原图文字了，框框没到」「卡这里过不去了」。查出来是两处：

其一，`loupeGeom()` 把视窗中心 `clamp(鼠标位置, V/2, W−V/2)` —— 视窗只能整个待在画面内。
于是鼠标推到边角时，视窗中心最多走到离边 `V/2` 的地方就顶住了。68 MP 那张图上
`V/2 ÷ W ≈ 8%`：**框框永远差 8% 到不了边**，再多推鼠标也不动 —— 「卡住了」就是这个。
改成中心钉在鼠标底下、允许视窗伸到图外（伸出去那半截由 `region()` 裁掉、取块只管图里那块，
光台上露出来的底色就是图外的留白）。

其二，十字框用的是 `left: (cx/W)%` —— 把**中心**当左上角摆了，整个框往右下偏了整整半格。
所以框和放大镜里显示的根本不是同一块画面。改成 `left: (vx/W)%`。

这两条任何一条单独修都不够，而且**都不报错、静态截图也看不出来**
（截图前都会先 hover 到画面中间，那儿的偏差最小）。
现在是 `shots.py --probe` 里那个 `probe_frame()`：鼠标推到四条边 + 四个角，
逐个断言「框左上角 == 视窗左上角」以及「贴边时框得贴到边」。
这个探针是**先把旧代码装回页面跑过一遍确认会失败**才留下的 —— 否则写个永远通过的空测试毫无意义。

顺带踩到探针自己的坑：`getBoundingClientRect` 是半开区间，鼠标取正好 `b.x+b.w` 那个点时
其实落在元素外，浏览器不派 `pointermove`，页面的 `S.at` 就停在上一处 ——
探针读到"假的老值"，四个角全是假数据（第一版就是被这个骗了）。现在贴边一律往里让一个像素，
并且等到 `S.at` 真的更新了再量，不靠 `sleep` 猜。

**10. 「看得到框框就看不到放大镜」—— 两块各自定尺寸，加起来比一屏还高。**

用户的原话是「你看 这就是鱼和熊掌不可兼得了」，两张截图分别是滚到光台上的框框、
和滚到放大镜。先量再说：光台 596 + 间隔 145 + 放大镜 437 = **1178 px**，而窗口能用
的视口只有 **982 px**，差 196。拆开看这 196 从哪来：

其一，**那句「结果存哪了」的提醒横在两块中间**，一句 41 px 的框，加上 flex 的上下
各 22 px 空当，一共吃掉 **63 px** —— 它是"一句话"，但位置比看起来贵得多。它本来
挂在光台的下载键旁边，搬去左边控制台「开始放大」底下反而更顺：按完键就在那儿
告诉你结果落在哪，文案里那句「右边的下载」说的也还是右边那一栏，没说过头。

其二，剩下的 133 px 全在两块自己的固定开销里：光台的长边原来按 `56dvh` 算（596），
三格按栏宽算（277）。两个都是"各自够大"，但没人管它们加起来有多高。
现在两个尺寸都改由视口高驱动（光台 `40dvh`、三格 `25dvh`），系数是解出来的：
光台 + 三格 ≤ 视口 − 262（间隔、标题行、取景行、图注、说明加起来是死的），
`0.40 + 0.25` 留出的余量正好让 800 px 高的视口也同得了屏。

改版式这种事最容易"看着对了"就收手，所以 `shots.py` 里加了 `fit` 这条断言
（光台顶到放大镜底这段总高 vs 视口高），并且照老规矩**先把它证死**：
临时用行内样式把光台的长边改回 `56dvh` 再量一遍，它必须当场翻脸（差 74 px 报错）。

**11. 双击启动的 `.bat` 里一个中文都不能留；换行还必须是 CRLF。**

两个坑叠在一起，而且都不报错 —— 表现只是"后面一半命令没执行"。

其一，**cmd.exe 是按字节偏移一行行读 `.bat` 的**。文件里只要出现多字节字符，
它的"字符数"和"字节数"就对不上，读到后面就错位了：实测报出 `'d'`、`'\pip'`
这种碎片，然后照着错位的字节继续往下执行。第一版还有个诱因是文件被存成了 **LF** 换行 ——
少一个 `\r`，cmd 同样对不齐。

其二，控制台编码。`.bat` 里的中文 `echo` 在 GBK 代码页下会糊，而 `server.py` 要打印的
`✓` `✗` `²` `−` 这几个字符 **GBK 根本编不出来**。所以「把控制台切到 UTF-8」和
「`.bat` 保持纯 ASCII」得一起做，只做一半就总有一半是乱的。

现在的分工是：**`.bat` 一个中文字都没有，只负责找到一个能用的 Python**，
之后所有中文提示都从 Python 出，`chcp 65001` + `PYTHONIOENCODING=utf-8` 保证它说话清楚。
既然提示都搬进 Python 了，就顺手把三步串进 `app/server/bootstrap.py` 统一收尾（失败停住等回车、
端口被占怎么说）—— `.bat` 和 `.sh` 因此都只剩二十来行，两边行为也一致，省得各改一遍。

两个附带的坑：

- `bootstrap.py` 里每次派生子进程前后都强制 `flush`。不然输出被重定向或走管道时，
  父子的缓冲各走各的，子进程的话会插到提示前面去，看着像顺序错乱。
- 子进程一律显式带上 `PYTHONIOENCODING=utf-8`。`.sh` 那边没有 `chcp`，
  不钉一下中文就按系统编码出去变乱码 —— 和 Windows 那边对齐。

**12. 同参数下本地比 bigjpg 糊 —— 一半的锅在「界面上排第一的那个预设」。**

用户的反馈很具体：「最高参数跟 bigjpg 4x 卡通同一张图，我这边最高都比不过」。
第一反应是参数不对（降噪档、权重族），于是五个预设 × 五档降噪全扫了一遍 —— **假设被证伪**：
同参数下全在 bigjpg 那版的三成上下，而且降噪档越高反而越锐（noise3 的拉普拉斯方差 133 > noise0 的 72），
跟"降噪把细节抹平了"正好相反。

于是开始怀疑模型本身，把每个预设的最高档单独拉出来、只比**细节热点区**（眼睛+发丝），
终于看到那条断层：**原生 4× 一次推理的模型能到 bigjpg 的 107%，2× 串联两次的只有 29~37%**。

```
动漫插画 4x-AnimeSharp（原生 4× 一次）   3512  → 107%
通用场景 Real-ESRGAN x4plus              1219  →  37%
卡通/插画 waifu2x CUnet（2× 串联两次）   1133  →  35%
插画高清 waifu2x Swin（2× 串联两次）       936  →  29%
                                          （bigjpg 4x 卡通 = 3279 = 100%）
```

**串联两次就在丢细节** —— 这是根因，不是锐化能补的。
而且还有一层人祸：最该选的那档（4x-AnimeSharp）原来排在**最后一个**，
名字叫「动漫线稿」、说明写着「线稿专用」，谁看都以为跟自己那张彩色插画没关系；
排**第一个**的偏偏是最弱的那个。所以用户不是选错了，是界面把人带错了。

修法两手：把 `anime` 提到第一位并改名「动漫插画」、说明写清「彩色二次元插画 / 原画」，
网页和 CLI 的默认预设都跟着改成它（顺带更快 —— waifu2x 系在 DirectML 上会算错只能跑 CPU，
4x-AnimeSharp 跑 GPU）。

**还有一个想当然的坑：锐化不是万能的。** 一度想把增益从 2 拉到 6 硬追 —— 数值上确实追上了
（锐度 2241 盖过 bigjpg 的 2007），但局部对比度 62.9 vs bigjpg 的 41.3、平块噪声 ×3。
bigjpg 的指纹恰恰是「**低对比度拿到高锐度**」（41.3 / 2007），那是真细节的形状；
靠拉对比度凑出来的高锐度是另一个东西。**指标能对上，观感对不上** —— 这条得靠并排看图才发现。

教训有两条：
- **画质比对别只盯参数，先把「每个模型单独跑一遍」排除掉。** 同族模型之间的差距能有好几倍。
- **界面上排第一的选项就是事实上的默认，它会决定用户拿到什么。** 排序不是装饰。

收尾锐化（第 5 步「线条要多清楚」）仍然保留，它治的是另一件事 ——
网络出来的边天生是渐变的（1 px 的线摊成 4~7 px 灰带），这一步把边缘收回硬边；
平坦区 32×32 块的 std 始终 `0.00`，不造噪。**它是调味，选对预训练权重才是主菜。**

**13. 把「绑定的地址」当「能打开的地址」用 —— 服务好好的，浏览器说访问不了。**

双击 `start_web.bat`，窗口里该显示的都在，最后一行写着：

```
已经替你打开浏览器： http://0.0.0.0:8765/
```

浏览器里却是「**嗯…无法访问此页面**」（Chrome 报 `ERR_ADDRESS_INVALID`）。

原因不是端口、也不是服务没起来 —— `0.0.0.0` 是**绑定用的通配地址**，它的意思是
「所有网卡都收」，那是给 `bind()` 看的；它本身**不是一个能连的目的地址**，
浏览器拿它当目标会直接拒。服务从头到尾都是好的（同一个进程用
`http://127.0.0.1:8765` 和 `http://192.168.x.x:8765` 都打得开）。

根子在两行代码共用一个变量：`bind()` 用 `--host`，而**打印和开浏览器也用了同一个 `--host`**。
默认 `--host` 是 `0.0.0.0`（为了让手机也能连），于是这个字符串被原样拼进了 URL。

修法是**把两件事分开算**：绑在哪儿是一回事，从哪儿能打开是另一回事。
通配地址一律对外报 `127.0.0.1`，绑了所有网卡时**再附一条局域网地址**（绑 0.0.0.0 的用处
本来就是想让别的设备连，那就把该敲的地址直接给出来）。同时把「打印已启动」挪到
`bind()` **之后** —— 端口被占时先打一行"已启动"再报错，那行假消息最容易把人带沟里。

**顺手又踩了第二个坑：那条局域网地址一开始报错了。** 找本机内网 IP 的常规做法是
「UDP `connect` 一个外网地址，看内核挑了哪张网卡」—— 在这台机器上它每次都返回
**`198.18.0.1`**。那是 `198.18.0.0/15`，RFC 2544 的性能测试网段，被代理软件的 TUN 网卡占了，
而且**默认路由在它手上**，所以内核挑中的就是它。这不是内网地址，别的设备根本连不上 ——
等于把"浏览器打不开"换成了"手机打不开"。改成枚举所有网卡 + 探针兜底，再把
回环 / 链路本地 / 这几个虚拟网段滤掉（`192.168` 优先，其次 `10.x`、`172.16/12`），
现在报的是 `10.103.89.173`。

**还有一层：这功能坏了不许拖垮启动。** 滤网段的字符串一开始写成 `198.19.0.0/15`
（`ipaddress` 说它 host bits set，不合法），而它在启动横幅里被调用 ——
真发生就是"双击启动闪一下就没了"。所以外面包了一层降级：探测失败就只是不提示这行。
同时让 `smoke.py` 直接测真身（还额外模拟一次抛异常，确认降级路径真的走得通，
而不是写了个没人走的 `except`）—— **写错了在自检里报出来，别留给用户去踩。**

**顺着这条线还查出一件事：Windows 上"端口被占"根本不会报错。**
`http.server` 默认 `allow_reuse_address=1`，Windows 的 `SO_REUSEADDR` 语义允许
**第二个进程绑同一个端口**（Linux 会直接拒）。所以旧窗口还开着的时候再启动一个，
两边都打印"已启动"，而请求只会跑到后起的那个 —— 用户看到的是「我改了代码怎么没生效」。
现在启动时先真连一下这个端口（TIME_WAIT 里的旧 socket 不会 accept，所以正常重启不误报），
探到有人在服务就先给出提醒。

教训：**别把「能监听的地址」和「能访问的地址」当成同一个东西**，`0.0.0.0` 和 `::` 都只属于前者；
**「本机内网 IP」也不是一个能随便问出来的东西**，装了代理/VPN 的机器上尤其要当心。
顺带提一句，这也是「自检全绿但用户一用就崩」的典型 —— 我自己验收时一直显式加
`--host 127.0.0.1`，正好绕开了双击启动那条路。

**14. 藏东西要藏两遍：挪出屏幕，还得从可访问性树里摘掉。**

窄屏的控制栏改成了从底部拉起的抽屉，收起时整块 `translateY(101%)` 推出屏幕外。

截图上它确实不见了 —— 但它**还在页面上**：键盘的 Tab 照样能走进去，走进去之后就落在
一块被遮罩盖着、还在屏幕外面的区域里。用户按 Tab 只看到焦点凭空消失，以为页面卡了。
修法是同时给上 `visibility:hidden`（配 `transition:visibility 0s .28s`，等滑出动画
走完再摘，不然会看到它中途"啪"地消失）。

这条值得单独记一笔，是因为**它属于"看不出坏"的那类**：截图正常、像素对比正常、
「页面无 JS 报错」也正常，只有真去按 Tab 才发现。所以 `shots.py` 现在**两样都量** ——
位置（`top` 是不是真的落在视口下方）**和** `visibility` 是不是 `hidden`。
只量位置的话，一个还留在可访问性树里的抽屉照样能过检。

同一批里还顺手捡到一个更小的：页脚那个折叠栏的三角在窄屏上不见了。原因是为了把点击区
抬到 44 px，`summary` 被改成了 `display:flex` —— 而 Chrome 里 `display:flex` 的
`summary` **不画那个 marker**。于是「两个必须说清的坑」看着像一句普通正文，
没人知道它能点。补一颗 `::before` 画的三角就行（`.adv` 那一栏本来就是这么干的）。

## 关于"无损"

严格说超分不可能无损——小图里不存在的像素，大图必须凭空多出来。模型做的是"低损 + 符合视觉预期"：它按训练时学到的经验补出边缘和纹理。**照片、文字、细密网格这类高频内容，模型没有可靠先验，会编出不存在的细节**。别拿它去还原监控截图里的车牌和文件里的字。
